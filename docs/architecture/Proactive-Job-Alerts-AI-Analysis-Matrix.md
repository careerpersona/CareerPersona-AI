# Proactive Job Alerts — AI Analysis Responsibility Matrix

**Status:** Internal maintenance document
**Purpose:** Preserve clear responsibility boundaries between the 6 fixed AI analyses (locked at 6, per the blueprint's §21 Rule 8) and prevent future overlap if the feature is ever extended. Cross-check this table before adding, modifying, or debugging any analysis.
**Related:** `docs/architecture/Developer-Toolkit-Architecture.md` (toolkit conventions), the locked blueprint (https://claude.ai/code/artifact/779890b3-2265-42d7-b86f-94e78d2d56db), Phase 3's AI Justification report (deterministic-alternative reasoning per analysis).

| # | Analysis | User Question | Deterministic Inputs | AI Responsibility | Output Type | Downstream Consumers |
|---|---|---|---|---|---|---|
| 01 | Critical Opportunity Engine | Which opportunities need action **right now**? | Discovery Engine's already-assigned `tier` (critical/high) + `urgencyFactors` + `matchScore` + `confidenceTier`, already capped/ranked by `enforceDeliveryCaps` (`discoveryEngine.js`) | Write "Why This Is Urgent" (1-2 sentences) per already-selected candidate; order the small delivered set for display. **Cannot** select which candidates cross the daily cap — that's deterministic. | `{alerts: [{index, whyUrgent, displayRank}]}` (`aiPrompts.js`) | `alerts` table (digest_type=`daily_critical`) → Phase 5 Alerts UI; Analysis 05 (trust score numerator, missed-opportunity review) |
| 02 | Curated Weekly Pipeline | What's the best **weekly portfolio**? | Discovery Engine's `curated`-tier candidates, already diversity/balance-constrained (`applyDiversityConstraint`, `applyBalanceConstraint`) | Write a "Why This Week" rationale (1-2 sentences) per already-selected candidate. **Cannot** re-select, re-rank, or drop a candidate — selection/ordering is deterministic. | `{analyses.curatedPipeline: [{index, whyThisWeek}]}` (`aiPrompts.js`) | `alerts` table (digest_type=`weekly_curated`) → Phase 5 Alerts UI |
| 03 | Market Intelligence | What's the **market** doing relevant to this user? | `marketSignals.js`: `computeVolumeTrend`, `detectHiringFreeze`, `computeSalarySignal`, `computeSpeedOfFill` — all arithmetic over posting counts/salaries | Synthesize trend numbers into search-strategy guidance; correctly frame a broad slowdown as market-wide, never as a fit problem (explicit prompt instruction). | `{analyses.marketIntelligence: {finding, evidence}}` | `market_signals` table (`signal_type=weekly_analysis`) → Phase 5 Alerts UI / future Job Search context |
| 04 | Watchlist Activity Monitor | Which tracked **companies** show hiring signals? | `watchlistActivity.js`: `computeWatchlistActivityStates` — mechanical detection (new posting / volume increase / network-contact-joined / 30-day quiet), reading already-persisted `alert_candidates` grouped by company | Cross-company synthesis: which company deserves attention first, connecting signals across companies. **Weakest AI justification of the six** — flagged explicitly in the Phase 3 report as the first candidate to reconsider if the feature is ever trimmed. | `{watchlistSummary: {finding, evidence}}` | `market_signals` table (`signal_type=watchlist_summary`) → Phase 5 Alerts UI |
| 05 | Alert Effectiveness Analysis | How well is **the alert system itself** performing? | `effectivenessMetrics.js`: `computeAlertTrustScore` (explicit formula from the blueprint), `findMissedOpportunities`, `computeOpportunityEngagementTrends`, `computeDiscoveryCoverage` — all counts/ratios, zero AI | (a) Interpret trust score + coverage numbers; (b) hypothesize *why* a specific missed opportunity was likely missed (timing/confidence/urgency — no formula exists for this, explicitly framed as hypothesis not certainty); (c) note revealed-preference patterns | `{analyses.alertEffectiveness: {trustScoreFinding, missedOpportunityHypotheses[], preferenceNote}}` | `market_signals` table (`signal_type=weekly_analysis`) → Phase 5 Alerts UI; self-correction also writes `alert_learning_weights` deterministically (trust score < 40% → confidence floor raised, no AI involved in that decision) |
| 06 | Timing Intelligence | **When** should the user act, by opportunity type? | `marketSignals.js`: `computeApplicationWindowStats`, `computePersonalOutcomeTiming`, `computeSeasonalPattern` — all bucketed statistics over the user's own application history | Weigh potentially-conflicting signals (population pattern vs. this user's own history) into one personalized "Best Apply By" recommendation. | `{analyses.timingIntelligence: {finding, evidence}}` | `market_signals` table (`signal_type=weekly_analysis`) → Phase 5 Alerts UI |

## Cadence grouping (not a 7th responsibility — orchestration only)

| Cadence | Cron | Analyses | Why grouped |
|---|---|---|---|
| Every 6h | `0 */6 * * *` | 01 only | Only analysis needing near-real-time freshness (closing deadlines, referral timing) |
| Every 12h | `0 */12 * * *` | 04 only | Watchlist companies change slower than the general opportunity pool |
| Weekly (Mon 06:00 UTC) | `0 6 * * 1` | 02 + 03 + 05 + 06 | All four are inherently weekly-cadence by the blueprint's own design (weekly pipeline, weekly market read, weekly self-evaluation, weekly timing guidance) — bundled into one `askClaude` call per user per week, same conditional-section-inclusion pattern as Referral Intelligence, to avoid 4 separate AI calls for data that's only refreshed once a week anyway. |

## Adding a 7th analysis (if ever proposed)

Per blueprint §21 Rule 8, the count is locked at 6 — this is a **roadmap decision**, not a routine implementation choice. If proposed:
1. Write its row in this table first — user question, deterministic inputs, AI responsibility — before any code.
2. Confirm the question doesn't restate rows 1-6 above.
3. Confirm every input claimed as "deterministic" already has a real computing function (in `discoveryEngine.js`, `marketSignals.js`, `effectivenessMetrics.js`, or a new sibling module) — never let the AI compute a fact no deterministic function produces.
4. Apply the same AI Justification standard used above: name the deterministic alternative considered and explain precisely why it's insufficient.
